# From the dev announcements

Notices and polls in the title-bar bell (source `dev`, kinds `dev-notice`, `dev-poll`, mute key `dev`).

- Feed: `website/public/announcements.json` is `{"payload": base64(JSON), "sig": base64(ed25519)}`, served at `https://ruforge.app/announcements.json`. The signature covers the decoded payload bytes.
- Signing: `node scripts/announce.mjs <keygen|list|poll|notice|remove|verify>`. The private key lives at `%USERPROFILE%\.ruforge\announce-ed25519.pem` (override with `RUFORGE_ANNOUNCE_KEY`) and never enters the repo. Every write re-signs. `keygen` refuses to overwrite a key; a new key means a new app release, since the public half is compiled in (`src-tauri/src/announcements/pubkey.rs`, `website/functions/_shared/announcePubkey.ts`).
- Publish between releases: `node scripts/publish-snapshot.mjs --only website/public/announcements.json --dry-run`, then `RUFORGE_PUBLISH=1 node scripts/publish-snapshot.mjs --only website/public/announcements.json "<msg>"`.
- App side: `src-tauri/src/announcements/` fetches on launch and every 6 h (release only), verifies, caches in app_data, and pings `main` with `dev-announcements`. `src/lib/devAnnouncementsHost.ts` pulls through `announcements_get` (main label only) and records `dev:<id>` once; a seen-set in localStorage keeps read or pruned rows from returning.
- Bad signature, JSON or version drops the whole file and keeps the last good cache. Invalid items are dropped individually. Items are hidden 60 days after `published`.
- Debug: `announcements_ingest_debug(body)` runs the same verify and deliver path from devtools. Debug builds never fetch.
- Voting is in-app. Clicking an option calls `announcements_poll_vote` (`src-tauri/src/announcements/vote.rs`), which POSTs to `https://ruforge.app/api/poll` (`website/functions/api/poll.ts`) and returns the tallies; `announcements_poll_tally` is the GET. Both are main-label only and refuse poll or option ids that are not in the verified cache. The voter value is a random 32-hex install id, created once in app data (`poll-voter-id`), never a hardware fingerprint. 10 s timeout, no retries.
- Client state is `src/notifications/devVotes.ts` (localStorage `ruforge-dev-votes-v1`: pick, counts, last read). `devSource` folds it into `ref.devVote` and drops the pick actions once the user has voted or the poll has closed. Tallies are re-read when the bell opens, at most every 3 min per poll, only for polls whose results are visible (voted or closed). Percentages never show before a vote (no bias). Failure leaves the options clickable with one inline error line, no toast.
- Debug builds only: when the endpoint fails (or the id is missing from the signed cache, like the `zz-test-*` rows) Rust returns deterministic mock tallies so the UI can be checked. Release builds never mock.
- The pick, tallies and install id never go in event payloads; they reach the overlay panel only inside the private-mailbox item state like every other row. `ruforge.app/poll` still exists for notice links but the app no longer opens it for polls.
- Cards live in `src/components/notifications/dev/`: `DevPollCard` (question, lettered one-line options, result bars) and `DevNoticeCard` (a message bubble with a squared tail corner). Two tones and two sizes per card, no badge.
- Polls render only the question and options; a poll body is never shown (Rust accepts an empty one, `announce.mjs poll` rejects `--body` and warns on a legacy body). Notices need a body.
